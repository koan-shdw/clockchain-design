01Overview

What the server is.

An MCP server that adds Clockchain consensus time, notarization, contract scheduling, audit trails and agent identity verification to any MCP client. It wraps the live node gateway at node.clockchain.network and does not change the blockchain protocol. R7

03Agents

Trust the agent on the other side.

Before agents talk business, they prove who is present and what each side agreed to. Signing happens on each agent's own machine, and the outcome is anchored where anyone can re-verify it. R1

05Why it holds

Proof, not assurance.

5.1Consensus time

Every timestamp is the network's agreed block time, and anyone can re-check it. There is no single clock to trust. R1

5.2Self-verifying receipts

A receipt carries its own payload and anchor. Recompute the hash and compare it with the on-chain block. R1R16

5.3Tamper-evident

Change one byte and verification fails. The ledger is append-only; the immutable block is the record. R1

06Install

Add Clockchain to your agent.

Hosted endpoint. Any MCP client connects in under a minute. R1R8

  1. Get a testnet token

    A delegated testnet token: writes spend Clockchain's testnet credits. No signup. R7

    curl -X POST https://mcp.clockchain.network/token

    Or bring your own Clockchain API key; writes then spend your credits. Send it in the x-clockchain-* headers, not in x-api-key, which is for MCP tokens only. R1

    Note for Rasesh · N7 Appendix B

    "How to get one" for an API key links to the clockchain.network home page R1. The page that issues keys belongs here.

  2. Add the server

    The same block works in every JSON-configured client: Claude Code, Cursor, Claude Desktop, Hermes, OpenClaw. R1

    MCP config · JSON
    {
  "mcpServers": {
    "clockchain": {
      "type": "http",
      "url": "https://mcp.clockchain.network/mcp",
      "headers": { "x-api-key": "<YOUR_TOKEN>" }
    }
  }
}
    CLI · where the client can set headers
    claude mcp add clockchain --transport http https://mcp.clockchain.network/mcp \
  --header "x-api-key: <YOUR_TOKEN>"
    Codex · ~/.codex/config.toml
    [mcp_servers.clockchain]
url = "https://mcp.clockchain.network/mcp"
http_headers = { "x-api-key" = "<YOUR_TOKEN>" }
# headless (codex exec) only: nobody is there to approve each call
default_tools_approval_mode = "approve"

  3. Verify

    Open a new session and run /mcp. You should see clockchain with all 50 tools. Then ask: "use clockchain to get the current consensus time." R1

    Local stdio install, ERC-8004 reads and chat-connector setup are in INSTALL.md. R8

07Limits

Limits and honest claims.

Rate30 tool calls per minute per token. The MCP handshake and tools/list are free. R2
TriggersUp to 20 active timers and alarms per caller. A fire is 1 s to 30 days out; intervals are 60 s or more. R2
CreditsEach anchor spends one testnet log credit: two per stopwatch measurement, one per timer or alarm fire. Reads and verification are free. R2
WebhooksOptional webhook_url on timer_set and alarm_set. Standard-Webhooks headers, HMAC-SHA256 signature with a per-caller secret returned once. Destinations are DNS-pinned and allow-listed. R2R13
BlocksBlocks mint only on writes, so consensus now goes stale on an idle chain. R9
NetworkAnchored on the Clockchain anchoring gateway: testnet, one validator. Hash, block anchor and block time are real and verifiable with no key. Multi-validator attestation starts at mainnet. R1R9
EvidenceNot yet a court-of-law evidentiary claim. R1
PackagesThe @clockchain packages are not on npm yet. Use the hosted endpoint, or clone and build the repo. R7
