MCP technical manual · Style guide

The main page, set as a manual.

The manual uses the main site's tokens unchanged: the same green, the same Inter Light headings with a green keyword, the same JetBrains Mono labels, the same light and dark themes. What changes is the structure: numbered sections, square blocks, tables, figures with captions, and a source on every claim.

01Principles

Five rules.

1.1Same brand

Only site tokens. No new colours except the note orange.

1.2Numbered

Every section, block and figure has a number a reader can quote.

1.3Sourced

Every claim carries a reference chip to its page, doc or repo file.

1.4Gaps shown

A missing or conflicting source gets a note for Rasesh, in place.

1.5Square

Blocks use a 6 px radius. Only buttons and status chips stay round.

02Colour

Site tokens, one addition.

Swatches show the current theme. Switch the theme to see dark values. Light values are listed; dark values live in site/styles.css under data-variant eclipse.

06Writing

Dry facts, item by item.

VoiceTech-manual facts. One claim per sentence. No sales words.
SourcesA claim without a source does not go in. If the source is missing, write a note for Rasesh instead.
PunctuationNo em dashes. Ranges use "to": 1 s to 30 d.
NamesProduct names as on the main page: Agent Handshake, Agent Contract, Timer, Stopwatch, Alarm. Tool names only in mono. No internal agent names and no model names.
StatusLive on testnet, or In development. Nothing else.
